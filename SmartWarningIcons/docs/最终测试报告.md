## 修复与证据

| 修复点 | 原因与验证 |
| --- | --- |
| 黄标图集、原版「即将减产」 | 实装 `Entity Sign Batch` 着色器采样的是 4 列 × 8 行图集。旧实现把黄色槽 25 写到了原版槽 7；红色槽 31 恰好不受影响。现在槽 25 写到像素坐标 `(256, 1536)`，保留槽 31 不变。GPU 回读对比原版槽 7，2,304 / 2,304 个样点均在容差内。见 [SignIcons.cs](<../src/SignIcons.cs#L144-L149>)。 |
| 红标、黄标与生产恢复 | 制造台和生产模式研究站共用判定。即使生产状态交替，高缓冲仍触发黄标；产物取走后恢复。验证制造台 60 次相位交替、两批阈值边界、红黄同时满足时黄色优先、缺料后补料消除红标。零时长和未就绪配方不新增误报或异常。见 [OutputPileSign.cs](<../src/OutputPileSign.cs#L22-L92>)。 |
| 科技切换、矿点共采 | 研究站只在当前科技与组件科技一致时比较矩阵；无科技或切换过程中不误报。最小矿点模式用原版方法刷新储量，不再等本机下一次扣矿。总量、最小量、等于阈值、油泵、水泵、供电警告和远程工厂均有断言。见 [OutputPileSign.cs](<../src/OutputPileSign.cs#L40-L54>)、[VeinDepletionSign.cs](<../src/VeinDepletionSign.cs#L39-L75>)。 |
| 开关、警报汇总和存档 | 原生按钮点击分别改动红、黄显示位，选项 XML 持久化成功，中英文提示正确。建筑自己的「警报」关闭后，顶部汇总的对应数量减少，建筑 `signType` 不变；两类开关互不代替。重复调用 `IconSet.Create` 不移动自定义图标索引。临时沙盒用原版流程写盘并读档，重新注册的信号、图集和 GPU 索引通过复验。 |
