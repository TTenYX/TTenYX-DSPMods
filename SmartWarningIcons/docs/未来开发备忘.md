# SmartWarningIcons 未来开发备忘

> 记录日期：2026-11-26（基于 1.1.1）。以下为候选方向，未排期、未设计定稿；动手前先核对当版源码、游戏版本与图集取证（方法见 `9.准则与参考/MOD-发布与分发排障.md`）。

## 1. 研究站科研模式提示优化

**已核实的现状**

- 研究模式红标（缺矩阵）仅在 `lab.techId == 当前科技` 且未生产、`matrixServed[j] < LabComponent.matrixPoints[j]` 时显示；未需求的矩阵槽需求为 0，不参与判定（不会误报）。
- 原版面板对无科技的研究站显示「等待科技」（`lab.techId == 0`），但建筑顶没有专用图标——原版对研究模式站的 sign 写入逻辑在 `FactorySystem.GameTickLabResearchMode`（写 4/6 的具体分支待核实）。
- `LabComponent.matrixPoints` 是静态字段、按当前科技整体更新；科技切换当帧研究站可能仍持旧 `techId`——现有红标已按"techId 匹配当前科技"防护，扩展提示时必须保留。

**可考虑的方向**

- 「等待科技 / 无科技」专用提示：研究模式且无当前科技（或 `lab.techId == 0`）时显示，替代原版笼统的无配方图标。
- 「缺矩阵」是否要与「缺原料」红标区分（不同图案），目前两者共用 signType 31。
- 堆叠研究站（各站 `matrixServed` 独立）的聚合显示策略。

**前置研究**：新增槽位需先解码当版图集 alpha 选空槽（25/31 已占用；掩码 ≤31）；原版研究模式 sign 写入分支需反编译确认。

## 2. 放大射线接收站发电模式图标

**现状**：射线接收站的发电/产光子模式图标是原版绘制（走 sign 的 iconType/iconId 通道），本 MOD 未触碰。

**待研究**

- 原版在该站 `SignData` 上如何写模式图标（iconId0 通道还是 signType 通道），quad 尺寸由哪个字段控制（`SignData.w`）。
- 放大手段：逐站改写尺寸字段是否可行、是否影响图集采样/顶点布局/LOD；是"整体放大"还是"仅发电模式放大"；是否加配置开关。

**风险**：实体图标通道是全建筑共用的绘制路径，逐站改动需真机回归确认无连带影响。

## 3. 联动 FactoryLocator 显示自定义图标

**现状**：FactoryLocator（TEST 档在用 1.3.13）会汇总建筑状态，本 MOD 的自定义 signType 25/31 在其 UI 中大概率显示为空白或默认图标（FL 有自己的 signType → 图标映射，未证实）。

**切入点**

- 反编译 `FactoryLocator.dll`，定位它读取 `entitySignPool` 后的图标解析点：查 `IconSet.signalIconIndex` / `LDB.signals.IconSprite`，还是内置映射表。
- 若走现有后缀覆盖的入口（`SignalProtoSet.IconSprite`）则可能已兼容，真机验证即可；若走内置表，用 Harmony postfix 把 525/531 映射到本 MOD 的 sprite。
- 做成"尽力而为"联动：运行时检测到 FL 再挂补丁，不设 HardDependency；以 TEST 在用的 1.3.13 为兼容基线，FL 升级后回归。

**注意**：先看 FL 仓库是否已有自定义 signal 支持约定，避免与上游方案冲突。
