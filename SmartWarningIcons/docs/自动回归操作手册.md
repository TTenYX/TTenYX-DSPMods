# SmartWarningIcons 自动回归操作手册

适用于 Windows 上的 Steam 版《戴森球计划》和 BepInEx 5。自动测试会启动实际游戏并占用游戏窗口；运行前确认已有游戏实例已关闭。脚本检测到已有 `DSPGAME` 时停止，不会关闭其他实例。

## 构建

从仓库根目录执行：

```powershell
dotnet build SmartWarningIcons/SmartWarningIcons.csproj -c Release
dotnet build SmartWarningIcons/tests/SmartWarningIcons.SelfTest.csproj -c Release
```

[正式工程](<../SmartWarningIcons.csproj>)不编译 `tests` 里的源文件。[自测工程](<../tests/SmartWarningIcons.SelfTest.csproj>)仅在脚本设置了临时文档路径时运行，不随 MOD 部署或发布。

## 单 MOD 回归

保持 Steam 客户端运行，指定一个未使用的新标签：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File SmartWarningIcons/tools/run-selftest.ps1 -Label isolation-01
```

[回归脚本](<../tools/run-selftest.ps1>)读取现有 `TEST` 的 BepInEx 核心，但不加载其余 MOD。脚本创建单次启动目录，复制启动文件并链接游戏数据，把选项和存档指向临时目录。自测插件先核对存档路径，再自动进入新建沙盒。它在已启动的真实游戏中调用 Harmony 补丁所挂的帧末入口，使用构造的制造台、研究站和矿机对象做边界断言。黄标回归先调用原版生产更新，再验证有库存、堵停、出料恢复及缺料等状态。图标由游戏原版材质和实际 GPU 验证。

## 现有 TEST 档冒烟

单 MOD 回归通过后才部署。以下两条命令使用已建立的 `TEST`，不新建 r2modman 档：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File SmartWarningIcons/tools/deploy.ps1 -WaitSeconds 0
powershell -NoProfile -ExecutionPolicy Bypass -File SmartWarningIcons/tools/run-selftest.ps1 -UseTestProfile -Label test-profile-01
```

[部署脚本](<../tools/deploy.ps1>)只替换 SmartWarningIcons 的构建文件，受影响的旧文件备份到 `TEST/_backups-SmartWarningIcons`。BepInEx 不会扫描该档根备份。命令校验构建文件与部署文件的 SHA-256。

`-UseTestProfile` 使用现有 `TEST` 插件组合，先校验部署内容，只检查沙盒加载、图集、信号及选项项；不在多 MOD 进程中切换测试对象或配置。存档仍使用临时目录。运行末尾会等待已发现的 PlanetFinder 扫描线程结束，避免过早销毁它正在读取的星球数据。退出后移除本轮的临时自测插件，保留部署好的正式 MOD。

## 判定结果

运行目录位于 [docs/logs](<logs/>)下，以 `-Label` 区分。核对 `run.txt` 中的启动 PID、退出码和清理状态，并与 `selftest.log` 的断言结果相互印证。`LogOutput.log` 用于核对 BepInEx；`Player.log` 包含 Unity 日志和退出阶段信息。`rendered-signs.png` 记录原版着色器对四种掩码组合的画面。退出时若有新异常，不要仅凭断言数量判为通过。

在现有 `TEST` 中，已知 `BuildToolOptCAPIcompat` 与 `BlueprintTweaks` 的版本不兼容，以及 Free Camera 的旧 Harmony 补丁缺少目标方法。脚本仅对已识别的这两项区别记账，不忽略其他新异常。
