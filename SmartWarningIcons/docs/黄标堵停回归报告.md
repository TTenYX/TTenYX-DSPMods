# SmartWarningIcons 黄标堵停回归报告

测试日期：2026 年 11 月 20 日（北京时间）。对象：SmartWarningIcons 0.1.0 本地构建；游戏版本 0.10.35.29151、BepInEx 5.4.17.0、Direct3D 11。该报告更新了[首轮报告](<最终测试报告.md>)中的黄标判定，图集、显示开关和存档格式不变。

## 判定变更

旧版使用「产物缓冲超过两批或生产已堵停」的条件。两批不是原版的出料上限，因此仍在生产、甚至只是暂存产物的建筑也可能亮黄标，缺原料也可能被误标为产物堆砌。

新版[帧末判定](<../src/OutputPileSign.cs#L56-L73>)直接沿用原版制造台和生产模式研究站面板的状态：未在生产，并且进度已到完成线。原版产物缓冲装不下本批产物时会以该状态停止；出料成功但缺下一轮原料时则将进度归零。因此不再读产物存量，也不复制不同设备和配方各自的容量公式。

| 场景 | 预期 |
| --- | --- |
| 产物缓冲有库存，原版仍在生产 | 不显示黄标，包括产物刚好填满但下一轮已开始的情况 |
| 完成的一批产物放不进缓冲区，原版停工 | 显示黄色「产物堆砌」；多产物配方有一个产物堵满即会停工 |
| 腾出能容纳本批产物的空间，原版恢复生产 | 黄标在恢复生产的帧熄灭，即使缓冲区还有库存 |
| 本轮产物已入缓冲，但原料不足，不能开始下一轮 | 显示红色「缺原料」，不被存货覆盖 |

## 真机验证

[自测用例](<../tests/OutputStallRegression.cs>)在实际游戏进程中调用原版制造和研究站更新，再调用已打补丁的帧末入口。测试使用构造的设备状态与临时沙盒，不加载正式基地存档。

- 旧构建复现：34 项通过、9 项失败。失败项目均为库存误报、缺原料误标、或恢复生产后黄标不消失；已有失败时不执行后续写档和读档。见[基线断言](<logs/yellow-stall-baseline/selftest.log>)、[进程记录](<logs/yellow-stall-baseline/run.txt>)。
- 新构建隔离回归：45 项通过、0 项失败；游戏退出码为 `0`。原版制造台与生产模式研究站均实测到 `无黄标 → 堵停黄标 → 持续堵停黄标 → 复产熄灭 → 缺料红标`。双产物用例中，只腾出一个副产物的空间即可恢复生产、清除黄标。供电警告、矿脉警告、图标和临时存档重载也通过。见[完整断言](<logs/yellow-stall-verified/selftest.log>)、[BepInEx 日志](<logs/yellow-stall-verified/LogOutput.log>)、[进程记录](<logs/yellow-stall-verified/run.txt>)。
- 现有 `TEST` 档冒烟：4 项通过、0 项失败，运行 481 个工厂逻辑帧，游戏退出码为 `0`。仅出现已有的 `BuildToolOptCAPIcompat` 和 Free Camera 兼容报错，未发现本 MOD 新异常。临时自测插件和测试存档均已清理。见 [TEST 断言](<logs/yellow-stall-test-profile/selftest.log>)、[BepInEx 日志](<logs/yellow-stall-test-profile/LogOutput.log>)、[进程记录](<logs/yellow-stall-test-profile/run.txt>)。
