## 0. 一句话结论

**「距离太远」的根因不是"被删掉的中间节点"，而是长度模型把一格的经度弧长算小了 1.47 倍。**
一格经度的弧长 = `半径 × cos(节点纬度) × 2π/(区域经度分段×5)`，其中**分段数只由"区域锚点纬度"决定，对整片区域是一个常数**，而**节点纬度 = 锚点纬度 + y×0.36°**，可以离锚点很远。
`6k太阳帆` 是"单区域跨 3 个纬度带"的图：锚点坐在 600 格/圈的带里（47°），节点却一路铺到赤道。旧模型整片按 600 格/圈的下限纬度取 cos，于是赤道附近的跨度被低估 1.47 倍——模型 1.61 m 的合并段，游戏量出来 2.37 m，超过 2.3022 m 硬上限。

## 2. 新的长度模型（铁律的技术保证）

对每个区域求出**所有合法粘贴姿态**，取其中的**最大距离**作为判据：

1. **x 方向的弧长随节点纬度变化**
   `弧长 = 半径 × cos(节点纬度) × 2π/(5·S')`，`S'` 由**锚点纬度**决定（粘贴端 `BlueprintUtils.RefreshBuildPreview` ≈1948/1966 行）。
2. **锚点纬度只能落在它自己那个分段数对应的纬度带里**
   带表用游戏自身的 `PlanetGrid.DetermineLongitudeSegmentCount` 逐点核对（`--bandtable` 输出「✓ 全部一致」）。旧的 12 带表（来自 DataAnalysis 笔记）纬度是对的，但**格宽系数**在极地是错的（例：40 格/圈的真实每 x 单位弧长是 1.876 m，旧表写 1.430）。
3. **区域之间的比例必须守恒**
   `GenerateAreaGratBoxByBPData` ≈2485 行只校验 `父分段/子分段` 的**比值**，所以"整组分段数同比例缩放"也是合法粘贴；模型把 4 个真实偏航象限（`num=floor(yaw/89.9)`，90°/270° 会把 x/y 两轴互换）全部枚举。
4. **用蓝图自身的链节筛掉不可能的纬度**
   蓝图是游戏接受过的，所以"原件链节会超限"的纬度玩家根本粘不上去。把每个姿态切成 0.05° 的纬度格，只保留**全部原件链节都合格**的格子；再把 `Distance` 定义成"这些格子上限的最大值"。
   挑选证据链节时剔除"不可能是相邻带"的连接（最宽松模型下仍 > 2×硬上限，例如整球图上跨 30 格的存储连接），否则会误判所有姿态。
   若一个可用纬度都找不到 → `Unverifiable` → **不做任何合并**（宁可零收益）。
5. **x 绕圈折返**：整球区域的 x 是一整圈，接缝两侧（x=599.4 与 x=0.1）实际相邻。旧模型把它们算成 778 m 的"超长链节"——**那 47 条超长全是接缝假象，不是真超长**（这条旧结论已证伪，见 §4）。

### 6k 的实测模型
```
区域0:分段120→第3纬度带(46.98°~55.98°)，节点纬度 0.2°~47.7°（跨3带），每x单位 1.427~2.096 m
可行粘贴姿态 2 个（4 个偏航象限中只有 2 个通过原件自检）
最长原始链节 2.290 m（≤ 游戏硬上限 2.3022，模型自洽 ✓）
```
旧模型整片用 1.4265 m/单位 → 赤道端真实 2.0965 m/单位，**低估 1.47 倍**，与玩家实测 2.46/2.58 m ÷ 优化上限 1.615 m ≈ 1.52 的量级吻合。

## 4. 被证伪 / 被保留的判据

### 被证伪（不要再捡回来）
1. **「游戏粘贴时按邻近关系重算链路」** — 证伪。
   `BuildTool_BlueprintPaste.InitBuildPreviewByBPData`（`BlueprintUtils.cs:1541-1542`）把蓝图里存的连接**原样**拷进 `BuildPreview.output`：
   `buildPreview.output = _bpArray[blueprintBuilding.outputObj.index + num3]`。
   只有两种情况会改写：`ArrangeOverlapBP`（同位置预览互相覆盖时按位置重指）与 `MatchInserter`（分拣器端点缺失时就近匹配，0.8 m 球）。
   → 因此任务书里的 A「被删掉的中间节点是游戏就近重算所需的锚点」**前提不成立**：删掉节点不会让游戏拼出更长的带，只会让连接缺失。
   （A 仍然实现了，见 §1，作为跨纬带蓝图的兜底守卫；在本次全部实测图上触发 **0** 次。）
2. **「离线报出的 47 条超长链节」** — 假象，已定位为**经度接缝折返**（`#2258(x=599.44) → #2257(x=0.12)`，最宽松上界 778 m、修正后 1.11 m）。旧模型两个方向的后果：误报超长 + 不敢合并跨接缝的链。
3. **「一格的弧长是常数 1.2566 m」以及 DataAnalysis 笔记里的极地"格宽系数"** — 在极地错得最多（真实 1.876 m vs 表里 1.430），已改为由游戏函数直接推导并用 `--bandtable` 逐步校验。
4. **旧夹具「10 节点 → 7 节点」** — 在当前上限下不可达（1 格步长 1.2566 m，两步 2.5132 m 已超游戏上限），说明旧模型当年确实"合并了不该合并的东西"。夹具已改成检查不变量。

### 保留（本轮验证仍然有效）
- 被分拣器/建筑引用的带节点**一律固定、引用不改指**；额外定点护住 **+后继 +前驱**。
- 合并后仍跑 `InserterBinder` 逐端点判定/重绑。实测全部蓝图**空端 0、悬空 0**。
- 带间安全步进 + `capForOptimize = cap × 0.85`。
- `BeltWindowRepair` 仍**停用**（1.414 m 只是"连接缺失时就近接上"的窗口，不是已存连接的判据）。

## 5. 遗留风险（明确写出）

1. **`极地348锅（大塔）` / `极地密铺小太阳E` 现在省带 0**：模型在这两张图上找不到任何"原件链节全部合格"的纬度格。原因是它们原件里存在一类无法用"带-带相邻"解释的存储连接（整球图跨几十格）。**这是保守选择，不是 bug**；要恢复收益需要先弄清这类连接的来源（可能是旧的仙术/派生存档）。
2. **`Unverifiable` 判定依赖"原件链节 ≤ 硬上限"这一前提**。若某张图的原件本身就超限（游戏会拒绝），模型会保守到不合并。安全，但收益为 0。
3. **偏航象限**：模型枚举 4 个真实偏航（0/90/180/270），其中 90°/270° 会交换 x/y 两轴。对 6k，这两个象限被"原件自检"排除（原件在该姿态下会超限），因此不影响收益；但对别的图可能变保守。
4. **分拣器"失效"的定义**：铁律②的离线判据是"空端 0 / 悬空 0 / 逐端点可判定"，与玩家在 `UIInserterWindow` 里看到的"输入端失效/输出端失效"**不完全等价**（游戏还会拒绝已存连接）。前一轮玩家实测 0 失效是在旧模型 + 三点保护下取得的；新模型只改长度、不动连接重绑逻辑，理论上不会更差，但**必须由玩家在游戏里复验**。
5. **性能**：模型要为每个区域枚举 4 个姿态并做 0.05° 纬度格筛选（每个格要对全部证据链节算一次距离）。6k（3175 带、3139 链节）离线跑完约 1–2 秒，游戏内为一次性按钮操作，可接受；若日后遇到更大的图（>1 万带）需要留意卡顿。
