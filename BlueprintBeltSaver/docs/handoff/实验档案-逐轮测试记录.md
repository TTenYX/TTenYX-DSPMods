## v3 定段固定 + 分区等分（004.12-b）

改动（`BeltPathOptimizer.cs`）：
1. **重采样分支重构**：旧「整体等分 + 撞障碍回填原始对」→ 新「定段固定 + 分区等分」——构造期对每个候选插值弧位预判（真实碰撞盒 / 无盒 0.8 格回退 / 节点球阈值 R_o−0.05 即守卫 v3 同款判据），命中弧位所在原件段两端固定；固定点把链切成区域，每区域独立等分插值（跨度数 = ceil(Lf/cap)，每段 ∈ (cap/2, cap]），碰撞失败与亚最小碎片段从构造上消失。
2. **重绑/守卫可重跑化**：BuildRebinds / RunRestoreAndGuard 抽成局部函数，供失败恢复路径重算。
3. **跨度校验原件相邻对豁免**（KeptOver 口径，与离线矩阵 BuildSpanIndex 一致）+ 失败格点回退兜底（保留）。
4. 诊断计数：GridFallbacks / KeptOverSpans / 新链状态 optimized_grid_fallback。

### 发现并修复：准则⑦拓扑门禁的两处缺陷（并发会话 13:33 新增代码）

用 `.workb-topoprobe` 探针实证（1080 蓝图）：
1. **对象身份跨 Clone 失效**：`VerifyTopology` 用原件对象集匹配 Clone 侧 result 对象——`Clone()` 是深拷贝，映射恒空（mapped=0），带分拣器的蓝图会被误判"被跨线重绑"整单拒绝（1080 有 496 个分拣器/分流器）。
2. **门禁基线选错**：Clone 本身是游戏拷贝行为，序列化端点重载按位置重新吸附，贴近邻线时吸附到邻线节点（1080 分流器#238：原件 44 线 → 重载后 36 线），并非优化器所为。
3. **分流器目标被删后 binder 跨线兜底**：分流器(2014) 属 IsInserter(2011~2019)，目标删除悬空后 InserterBinder 就近兜底无线感知 → 跨线。修复：非插入器宿主目标被删时走臂长守卫同款 restoreIdx 通道回插原目标节点（引用原样保留，永远同线）。

**修复方案（已实施）**：门禁改为 **Clone 基线语义**——合并改写引用之前抓取 Clone 侧线路归属（preLines）与非带引用所在线（preRefs），只对账"优化器造成的改写"；映射用对象同源（preMerge↔result）直接比较。

## 第五轮实验与根因修复（2026-11-01 夜）

1. **bisect 五层指纹法建立**（自测插件 + 离线探针同式 FNV 指纹：源→Clone→格点后→插值后→采纳后，含引用拓扑哈希）。首版 bisect 有缺陷（误读 gArgs[0]），修正后**判决：游戏内与离线五层指纹逐字节一致**——合并结果无分歧，分歧只在门禁判定层。
2. **门禁基线分支错配修复**：采纳插值试验后 `bp = trial`，但门禁/binder 的基线表仍停留在 work 分支的对象集（按对象身份键控，跨分支不通用）→ 对账恒空 → "基线线#N→结果线#N（同号）"误拒全部蓝图。修复：trial 分支单独抓取基线（preMergeLinesT/RefsT），采纳时同步切换。
3. **CreateNew 缺头部导出失败修复**：trial 是 `CreateNew(快照)` 产物（私有构造不调 Reset、缺头部字段），其 Clone/导出序列化失败（实测"Clone 返回空"）。修复：采纳时把 trialBuildings 搬回**头部完整的 source.Clone() 底板**再交付（`var rebuilt = source.Clone(); rebuilt.buildings = trialBuildings;`）。
