# BlueprintBeltSaver 蓝图省带

独立 BepInEx 5 插件，把"蓝图传送带短带合并为长带"从 `DSPBlueprintToolsFixed` 中独立出来，并合并 LongerBelts 的"徒手拉带可用长带"能力，在蓝图信息窗口提供一键"长带优化"。

- 工程位置：`01.我的MOD\BlueprintBeltSaver\`
- 产物：`bin\Release\netstandard2.1\BlueprintBeltSaver.dll`
- 部署目标：`profiles\0.10.35 new\BepInEx\plugins\BlueprintBeltSaver\BlueprintBeltSaver.dll`
- 插件 GUID：`com.dsp.blueprintbeltsaver`

## 功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 徒手拉带长带 | 经纬线模式按跨度吸附、测地线（斜坡带）按间距分段，含阿基米德螺线模式与最短距离不限开关；垂直带自动微倾斜 |
| F2 | 设置窗口 | 三个滑杆同时驱动徒手拉带与蓝图优化上限，快捷键默认 `LeftAlt + B` |
| F3 | 蓝图长带优化 | 复制自已验证的 `BeltPathOptimizer` + `BeltDistanceMetric`，支持高空带子与全纬度换算 |
| F4 | 信息窗口按钮 | 在"新建属性"按钮下方注入"长带优化"，点击先干跑并弹确认窗（按等级分列），确认后刷新窗口、写回剪贴板并同步粘贴工具 |
| F5 | 避让 | 检测 LongerBelts / DSPBlueprintTools，避免同一方法被双重转译 |

## 配置（BepInEx Config）

| 配置 | 默认 | 说明 |
|---|---|---|
| `General/Enabled` | true | 总开关；关闭时不打补丁、按钮不生效 |
| `General/WindowHotkey` | LeftAlt + B | 设置窗口开关 |
| `Belt/CurrentDistance` | 1.9 | 最远距离（米）；未装 LongerBelts 时也是蓝图优化上限 |
| `Belt/LongitudeDistance` | 1.75 | 经纬线模式跨度 |
| `Belt/LatitudeDistance` | 1.5 | 经纬线模式跨度 |
| `Belt/LongerOnGrid` | false | 启用经纬线模式更大跨度 |
| `Belt/SlopePathMode` | 0 | 0 原始 / 1 阿基米德螺线 |
| `Belt/ShortestUnlimit` | false | 忽略最小间距（测试用） |
| `Belt/RebindSorterLinks` | false | 允许合并被分拣器/建筑引用的带节点，并把其连接重绑到新合并段（带三重守卫，详见下文） |

除上表外未增加配置项。

## 避让规则（F5）

- 已安装 **LongerBelts**（GUID `shisang_LongerBelts`）：不打 F1 的两个 Transpiler（避免同一方法双重转译），F2/F3/F4 照常；蓝图优化上限**每次优化时实时**读 `LongerBelts.LongerBelts.currentDistance`。
- 已安装 **DSPBlueprintTools**（GUID `dsp.byboy.blueprinttools`）：仅在日志提示功能重叠，不做屏蔽。

注意：目标 profile `0.10.35 new` 已安装 `shisang_makuwa-LongerBelts`，因此该 profile 下 F1 会主动让给 LongerBelts。若要验收"未装 LongerBelts 时的徒手拉带"，需在未安装 LongerBelts 的 profile 中测试。

## 与 LongerBelts 的差异（重要）

1. **代码基线**：F1 以 LongerBelts **1.5.1 干净源码**为基线（1.5.3 只提供反编译产物，含 `((Vector3)(ref x))._002Ector` 这类无法编译的转写残留）；间距常数按 **1.5.3** 取（最小 `0.400001`、常规上限 `2.301172`）。
2. **采用 1.5.3 的两处修正**：阿基米德模式下起点按真实半径缩放；经纬线模式增加极点保护。
3. **修正了 LongerBelts 在本版本失效的转译器**：`BuildTool_Path.DeterminePreviews` 的 `begin/end` 在 0.10.35 程序集上位于调用点前 `-23/-22`，而 LongerBelts 硬编码 `-22/-21`，实际取到的是 `end` 与 `int path`，会生成 `ref int` 传给 `ref Vector3` 的非法 IL。本 MOD 改为按参数模式自动定位这对 `Vector3` 局部变量，并在其读取前插入倾斜调用，不再依赖固定偏移。
4. **未实现 1.5.3 的 `ClampMaxDistance` / `DistanceUnits`**：计划书配置表未列，且 1.5.3 默认关闭，默认行为一致。
5. **窗口文案**：两个跨度标签按计划书配置表（`LongitudeDistance = 沿纬线最远距离`、`LatitudeDistance = 沿经线最远距离`）；LongerBelts 自身标注相反，故界面用词与其不同，底层算法一致。
6. 设置窗口只使用局部 `GUIStyle`，不修改全局 `GUI.skin`。

## 已知问题与修复记录

### 1. 优化后触发原版 `OnCameraPostRender` 空引用（已修复）

现象：点"确认"后游戏弹出「游戏运行错误！…自动存档功能将被关闭」，日志反复出现
`NullReferenceException at BuildTool_BlueprintPaste.OnCameraPostRender`（IL 偏移 `0x4d`，即
`ldfld PlayerAction_Build::model`），说明 `actionBuild.model` 为空。

原因：`OnCameraPostRender` 的守卫只检查 `bpCursor > 0`（预览已装载），不检查玩家建造模型是否就绪。
旧版"确认"会**无条件**把蓝图塞进粘贴工具并调用 `ForceDetermineBP()`，在非粘贴场景也把 `bpCursor` 置为正数，
于是每帧命中该空引用。

修复：

1. 仅在 `UIBlueprintInspector.usage == Paste`、粘贴工具 `active`、且 `GameMain.mainPlayer.controller.actionBuild.model` 非空时才同步粘贴工具
   （游戏自身也只在 `usage == EUsage.Paste` 时调用 `pasteBuildTool.ForceDetermineBP()`）；其他情况只更新蓝图窗口与剪贴板并写日志。
2. 改为**就地修改** inspector 持有的蓝图对象（不再替换对象），并按游戏做法调用 `Refresh(true, true, true)`。
3. 额外防护：给 `BuildTool_BlueprintPaste.OnCameraPostRender` 加前缀，当 `bpCursor > 0` 而建造模型为空时跳过本帧绘制；
   补丁安装失败只记日志、不中断（fail-soft）。

### 2. 极地蓝图的米制换算错误（已修复）

旧实现用「区域分段数反查纬度」推算经度缩放，遇到 `areaSegments` 表中不存在的值（例如 4）会失配并**静默退回 `cosBound = 1`**，
把该区域每格算成约 **62.8 m**（实际约 1.26 m），导致这类蓝图的链路几乎无法合并。

现改为与游戏设计一致的恒定每格弧长：游戏让区域经度分段数随 `cos(纬度)` 变化，步进角与 `cos` 因子相抵，故每格世界距离基本恒定。
蓝图不保存绝对放置纬度，因此取该恒定值（最大格距）作为保守估计，保证在任意纬度粘贴都不会产出越限段。

实测（`【极地】5发射+102弹射`，723 建筑 / 495 传送带）：

| 优化上限 | 结果 |
|---|---|
| 1.9 m（默认） | 495 → 488（省 7），174 条路径优化 3 条 |
| 2.301172 m（常规上限） | 495 → 475（省 20），优化 13 条 |

该蓝图原有 220 段相邻链节间距已超过 2.301172 m（按保守度量），属原有数据，优化器不会改动。

### 3. 打开设置窗口严重掉帧（已修复）

原因有三处每帧开销，全部落在游戏引擎耗时里：

1. `ResolveCap` 在窗口绘制时**每帧**调用 `AccessTools.TypeByName`——它会遍历所有已加载程序集的全部类型；
2. `DrawSettingsWindow` / `DrawConfirmWindow` **每帧** `new GUIStyle(...)`；
3. `SyncOptimizeButton` **每帧**给 `Text.text` 赋值（即使内容相同也会弄脏文本网格并触发重建）。

修复：反射结果缓存（未命中时每 5 秒才重试一次）、`GUIStyle` 按 GUI skin 缓存复用、`Text.text` 仅在内容变化时赋值；语言探测与按钮状态日志节流到 0.5 秒一次。窗口绘制只保留必要的实时读取。

### 4. 分拣器断链重绑（可选，默认关闭）

传送带若被非传送带建筑引用（分拣器取料/投料、建筑进料），默认实现会将其保留为锚点，链路因此在分拣器处断开。
配置项 `Belt/RebindSorterLinks`（默认 `false`）开启后，这些节点也可以参与合并，其引用会被**重绑到覆盖它的新合并段**。

重绑的三条守卫（任一不满足就保留该节点为锚点，绝不产出非法蓝图）：

1. **朝向一致**：被删节点与其覆盖段起点的 `yaw` 必须一致（容差 0.5°），保证分拣器校验期待的带方向不变；
2. **几何覆盖**：被删节点按弧长位置映射到覆盖它的那一段，重绑后的目标必然跨越原节点位置（校验：投影参数 `t∈[0,1]`、垂直偏差 ≤0.02 格）；
3. **字段不动**：只改写引用对象，分拣器的槽位（对带侧为 `-1`）与沿带偏移 `inputOffset/outputOffset` 原样保留。

实测（`0-传送带（72）、分拣器（24）`：40 传送带 / 9 处附属连接；`【极地】5发射+102弹射`：495 传送带 / 107 处附属连接）：

| 蓝图 | 默认（关闭） | 开启重绑 |
|---|---|---|
| 超市（40 带） | 40 → 32（省 8） | 40 → 30（省 10，重绑 4，朝向跳过 1） |
| 极地（495 带） | 495 → 488（省 7） | 495 → 484（省 11，重绑 62，朝向跳过 0） |

两次开启重绑的校验结果均为：悬空引用 0、几何越界 0、槽位/偏移被改动 0。默认关闭时算法路径与之前逐字一致（三份蓝图结果不变：省 8 / 省 7 / 1080 图 1553 段）。

仍**只能靠游戏内确认**的部分：分拣器沿带偏移合并后对应的物理落点、以及精确配速产线是否存在吞吐节奏变化。开启后确认弹窗会显示重绑数量与朝向跳过数量，并提示先在粘贴预览中确认无红色报错、分拣器可正常工作再保存。

### 5. 界面（省带按钮与确认弹窗）

- 蓝图窗口里的入口按钮名为 **省带**，尺寸与下方「复制」按钮一致；显示条件只要求"当前打开了一份含传送带的蓝图"，因此**蓝图库**与**世界内粘贴**两种界面都会出现。优先贴在「新建属性」下方；该按钮在某个界面不可用时，自动改为贴在「复制」左侧（日志打印 `省带按钮已注入：…`）。
- 确认弹窗不再自绘，改用游戏原生 `UIMessageBox`（与 UXAssist「初始化本行星」同一个弹窗）：标题 `BlueprintBeltSaver 蓝图长带化`，左侧告警图标，正文首行为传送带总数变化，其后每个发生变化的等级一行（无变化的等级省略），末行为当前上限与重绑统计，底部为「取消 / 确定」。
- 等级名称使用 `ItemProto.iconNameTagString`（形如 `\tag-;`）。DSP 把 UGUI 的文本生成器替换为 `UnityEngine.UI.Youthcat.TextGenerator`，其 `TextIconMapping.GetIconInString` 会解析该标签，因此**任意 Text 都能内嵌物品图标**（科技树、蓝图上限文本都这么做）。

### 6. 长度模型：纬度带表（已修复，关键）

蓝图把坐标存成"格"（`BlueprintUtils.cs` 拷贝路径：`localOffset_x = 角度差 / GetLongitudeRadPerGrid(...)`），而一格的**实际经度弧长**随纬度变化（越靠近赤道越长）。现在按 **DataAnalysis 的星球网格表**直接查带：

- `areaSegments × 5` = 该纬度带的沿纬线格数：200→1000（**第一纬度带/赤道**）、160→800、120→600、60→300、40→200、32→160、20→100、16→80、8→40、4→20（**第十二纬度带/极点**）；
- 每带格宽系数（带下边界东-西格宽 ÷ 赤道格长）：1.0、1.092、1.134、1.115、1.052、1.112、1.216、1.137、1.198、1.107、1.430、1.291，取带下边界值即带内最大 → 任何跨度都是上界；
- 纬度方向恒为 1.2566 m/格（250 格 = 90°）；高度恒为 1.3333 m/格，水平弧长按海拔半径放大。

日志会打印带信息，例如：

```
间距模型：区域0:分段120→第3纬度带(46.8°~55.8°,600格/圈)，区域2:分段200→第1纬度带(0.0°~28.8°,1000格/圈)；样本 3092 条，最长原始链节 2.197 m（无需收紧）
```

模型再用**蓝图自身的原始链节**做上界校验：若最长原始链节超过硬上限（`sqrt(5.3) = 2.3022 m`）则整体收紧（合法蓝图必然不超过）。失效判定用**名义下限**（1.2566 m/格）做，避免把游戏粘贴时会重算的旧连接算进来。

**踩坑记录**：不要在带系数之外再按节点 y 偏移折算纬度——区域锚点本身就在该带纬度上，重复折算会把极地跨度放大 2.6 倍（曾导致 ×0.385 的错误收紧与校验失败）。另：一度把"几何超限的存储连接"当断点，结果极地图 144 条（35%）连接被误判、收益归零；已撤销——长度合法性由模型 + 校准 + 逐段复检保证，含超长连接的跨度自然会被拒绝。

### 7. 合并模式与分拣器偏移

- **保点模式（默认）**：只在原有节点里挑保留点（贪心取最远可达），不发明坐标。
- **插值模式**：按弧长均匀插值（LongerBelts 式），用于"原节点已到极限、保点无解"的密集蓝图。
- 插件策略：**保点优先；若保点省 0，则自动用插值重试，只有更省才采用**。日志打印 `保点模式无收益，改用插值模式重试：…`，确认弹窗也会标注所用方式。
- **分拣器偏移守卫**：分拣器的抓放目标 index 是目标带的**中心 buffer**（1 buffer ≈ 0.06 m），合并会移动段中心。重绑时仅在**确定越界**的情况下把 `inputOffset`/`outputOffset` 夹到新段半长内，并计入报告"修正越界偏移"。

实测（cap 1.9，重绑开启）：

| 蓝图 | 保点 | 插值 | 插件实际采用 |
|---|---|---|---|
| 6k太阳帆（3175 带） | 2788（省 387） | 2631（省 544） | 387（保点有收益） |
| 【极地】5发射+102弹射（495 带） | 495（省 0） | 487（省 8） | 8 |
| 37.5小火箭（2224 带） | 0 | 1893（省 331） | **331** |
| 2880太阳帆（高效）（1159 带） | 0 | 905（省 254） | **254** |
| 1080 传送带（1897 带） | 1640 | — | 1640 |

赤道蓝图（第一纬度带）的带子若已是 1~1.5 格，两条相加 2.52~3.77 m 就超过游戏上限 2.3022 m——此时**保点模式数学上无解**，只能靠插值。

### 7. 长带化后分拣器失效（已修复：逐个校验 + 重绑）

现象：合并后蓝图能铺设，但少量分拣器失效。实测对比（`37.5小火箭 （需求氘棒）` 原图 vs 用户长带化后保存的版本）：

| | 建筑 | 传送带 | 分拣器 | **端点为空** |
|---|---|---|---|---|
| 原图（游戏已验证） | 3127 | 2224 | 616 | **0** |
| 长带化后 | 2790 | 1887 | 616 | **8**（输入 3 / 输出 5） |

原因：那份保存版本的区域是 `分段160`（参考纬度 36.9°），原图是 `分段200`（赤道）——即蓝图被**粘贴到了另一个纬度带**。带 1 的格长是赤道格的 1.092 倍，合并后的跨度在那边被放大 ~9%，少数链节超过 2.3022 m 硬上限，游戏就把对应分拣器端点置空。

修复：合并完成后**对每个分拣器端点逐个校验，失效者重新绑定**（`InserterBinder`）：

- 空端 / 悬空 / 超过游戏距离上限 / 目标跨度完全不在分拣器附近 → 在 5.2 m 内按"距离 + 方向偏好 + 跨度覆盖"挑最佳传送带并改绑；
- **机器端绝不改动**（分拣器另一端正常就是机器）；
- 只改写引用对象，槽位与沿带偏移（`inputFromSlot`/`inputOffset` 等）原样保留；
- 判据取自"游戏已验证"的原图：中心→目标带 ≤4.05 m；方向锐角 95% 落在 85~95°（故方向只作打分偏好，不作否决）；投影 t ∈ [−0.46, +0.60]。

验证：

| 用例 | 结果 |
|---|---|
| 用户的长带化版本 | 空端 8 → **0**（重绑 11 处，无可绑定 0） |
| 原图（游戏已验证） | 仅重绑 4/1232 = 0.3%，无误伤 |
| 端到端（原图 → 插值合并 → 校验） | 合并后空端 0、校验后 0、悬空 0 → **PASS** |

弹窗与日志新增：`分拣器校验：共 N 个，原有空端 A，重新绑定 B，无可绑定 C，原连接通过 D`。

**补救**：已保存的失效蓝图不必重铺——用新版再点一次「省带」，校验步骤会把失效端点绑回去。
